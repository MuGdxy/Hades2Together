# 开发路径

离线测试在仓库根目录执行 `lua tests/run.lua`。这一套测试必须在每个阶段结束后仍然通过。进游戏的验收另计，写在对应阶段的完成标准里。

## 阶段 0：边界

已完成，在 `main` 上。

协议、席位、队伍、死亡、血量放大、祝福归属、权威循环和假世界可以不启动游戏就跑通。`hack/game.lua` 有全部方法名，调用时会拒绝执行。插件能被 Hell2Modding 加载，但只打日志，不挂钩子。

## 阶段 1：同一台机器上的同一个世界

当前阶段。不打开网络，不启动第二个游戏进程。

目标是本机一个权威进程里有 4 个英雄单位，打同一只怪，血量只有一条。用这一阶段把引擎限制摸清：玩家数组只有 2 格，武器和索敌默认只认当前英雄。

顺序：

1. 在 `Ship` 旁装上 Hell2Modding，用开发目录里的 `src` 作为插件，确认日志里有 `phase 0 ready`。
2. 实现 `BindHero`。1 号用游戏里已有的英雄。2 到 4 号生成可操控单位，其中 3 号和 4 号不写入长度为 2 的玩家数组。
3. 实现 `PushInput`，本机能够驱动这四个单位。
4. 实现 `SetAggroTargets`，敌人可以把四个人都当作目标。
5. 实现 `SetCamera`，镜头框住还活着的英雄。
6. 把 `ReadActors` 和 `PullEvents` 接到权威循环上。在训练场或一间房里打一只怪，确认 `ReadActors` 里这个敌人只有一条 `hp`，两个人打它时这条血往下掉。

完成标准：

- 本机同时存在 4 个会动的英雄单位。
- 对同一个敌人 id 的伤害落在同一条血上。
- 敌人的目标列表里可以出现这 4 个单位。
- 镜头能框住存活的英雄。
- 新增的游戏调用只在 `src/hack/game.lua`。
- `lua tests/run.lua` 通过。

这一阶段不实现 UDP、不把快照发给另一个进程、不处理祝福界面和选门、不处理专用服务器的后台模拟。

## 阶段 2：主机即服务器

接上真实传输。客人发 `Input`，权威结算，回 `Snapshot`。客人调用 `SuppressLocalSim`，自己不再生成遭遇，只按快照画人和怪。

完成标准：两个游戏进程里，客人的攻击让权威进程上那只怪的血下降，客人屏幕上看到的是同一条血。

## 阶段 3：跑起来的规则

把死亡、开门、路线和祝福接成命令。祝福通过 `RunAsHero` 进入游戏自己的抽取。死亡后是继续还是结束，以 `gameplay` 的命令为准，再由 `hack/game.lua` 执行。

完成标准：一人倒下时其他人能继续打同一只怪；全灭时权威发出 `EndRun`；一次祝福只发给命令里指定的那个席位。

## 阶段 4：专用服务器

同一套 `serve`，玩家席为 0。实现 `SetFocusTick`，窗口在后台时模拟不停止。断线的名字回到原来的席位。

完成标准：权威进程没有本地英雄，客人仍能打同一只怪；把权威窗口切到后台后，客人的输入仍被结算。

## 阶段 5：手感

本机移动先预测，远程的人和怪按快照插值。远程动画先做待机、跑和冲刺。

完成标准：客人自己的移动在输入后立刻动起来，权威纠正位置；远程单位不在两拍快照之间停住。

## 阶段之间怎么推进

上一阶段的完成标准没有达到时，不开始下一阶段。某一阶段里如果必须调用游戏，调用写进 `hack/game.lua`，并在接口上加方法，而不是在 `gameplay` 或 `authority` 里直接读游戏全局变量。
